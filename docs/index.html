프로젝트 배경

신발은 브랜드마다 사이즈 체계가 달라 실제로 신어보지 않으면 맞는지 알기 어렵습니다.
온라인 구매의 반품률이 높은 근본적인 이유입니다.
그렇다고 매장을 방문하면 직원의 응대가 부담스러워 자유롭게 신어보기 어렵다는 불편함도 있습니다.

이 두 문제를 동시에 해결하기 위해 "직원 눈치 없이 마음껏 신어볼 수 있는 반무인 신발 매장"을 목표로 삼았습니다.
AMR과 로봇팔을 연동해 고객이 선택한 신발을 자동으로 가져다주는 자동화 매장 시스템 Moosinsa를 구현했습니다.

Depth 카메라 없이 2D 단안 RGB 카메라만으로 임의 위치·각도로 놓인 신발 박스를 인식하고 파지 좌표를 계산해 자율적으로 Pick & Place를 수행하는 비전 파이프라인 구축.

① Depth 센서 없이 3D 좌표 복원

Ray-Plane Intersection — "상자는 항상 Z_surface 위에 있다"는 물리적 제약 하나가 광선과 평면의 교점을 유일하게 결정합니다.

# core/coord_transform.py
ray_c = K_inv @ [cx, cy, 1.0]
ray_b = R @ ray_c
t = (z_surface - origin[2]) / ray_b[2]
P = origin + t * ray_b   # mm

픽셀 좌표 $(c_x, c_y)$를 카메라 내부 파라미터 $K$로 역투영해 카메라 공간의 단위 광선을 구하고, Hand-Eye 행렬 $R$로 로봇 베이스 공간으로 변환합니다.
광선의 파라미터 $t$는 "광선이 테이블 평면 $Z = Z_{surface}$와 만나는 지점"에서 결정되며, 최종 3D 파지 좌표 $P$를 얻습니다.
$$\mathbf{r}_c = K^{-1}\begin{bmatrix}c_x\\c_y\\1\end{bmatrix}, \quad \mathbf{r}_b = R\,\mathbf{r}_c, \quad t = \frac{Z_{surface} - o_z}{r_{b,z}}, \quad P = \mathbf{o} + t\,\mathbf{r}_b$$

오차 허용 기준 ≤5 mm — 그리퍼 파지 폭(약 40 mm)의 1/8 이내면 파지에 영향 없다는 오차 예산으로 설정. 트레이드오프: 물체가 평면 위에 있다는 도메인 가정 필요.

② Hand-Eye 캘리브레이션

AX = XB (Tsai-Lenz), 25포즈, Hand-Eye RMS 오차 1.245 mm.

# 각 자세마다
A_i = T_base2flange   # 관절각 → FK
B_i = T_cam2board     # solvePnP
# 25쌍 → Tsai-Lenz
X = cv2.calibrateHandEye(TSAI)

로봇이 자세를 바꿀 때마다 Flange 기준 변환 $A_i$와 카메라 기준 변환 $B_i$를 쌍으로 수집합니다. 두 변환은 구하려는 Hand-Eye 행렬 $X$에 대해 아래 관계를 만족하며, 25쌍의 방정식을 Tsai-Lenz 알고리즘으로 연립해 $X$를 추정합니다. $$A_i X = X B_i \quad (i = 1, \dots, 25)$$ $$X = T_{\text{flange} \to \text{cam}} \quad \text{(카메라가 Flange에 고정된 Eye-in-Hand 구성)}$$

왜 Flange 기준인가: TCP는 그리퍼에 따라 달라지는 가변값.
Flange는 공구 교체와 무관한 고정점이므로 그리퍼 교체 후에도 재캘리브레이션 불필요.

③ 이동 중 프레임 배제

로봇 이동 중 캡처된 흔들린 프레임으로 OBB를 검출하면 좌표가 틀려 파지 실패로 이어집니다. move_to()가 완전히 반환돼 로봇이 완전히 정지한 이후에만 검출 결과를 읽도록 순차 실행으로 보장합니다.

# nodes/vision_pick_place_node.py
self._motion.move_to(observe_pose)         # blocking
flange = self._motion.get_flange_coords() # Flange 좌표
self._transformer.update_pose(flange)     # T_base2cam 재계산
obb = self._detector.wait_for_detection(timeout=10.0)  # 정지 후 첫 프레임

Troubleshooting

문제 해결 2건

HSV 노이즈 오인식 → 형태 필터로 억제
증상
HSV 범위만으로 검출 시 바닥·벽·조명 반사 등 상자가 아닌 영역도 컨투어로 잡혀 잘못된 중심점 → 오픽업 발생
원인
HSV는 색상 조건만 걸러냄. 같은 색 노이즈를 배제할 형태 기준이 없었음
해결
컨투어마다 형태 필터 4종 적용 :
면적(10000~20000 px²) · 폭/높이 범위 · 종횡비(0.4~3.5) · solidity(>0.6).
인사이트
"색상은 필요조건, 형태는 충분조건" — HSV 단독으로는 같은 색 물체를 구분 불가
이동 중 흔들린 좌표 → 오픽업 → 게이팅으로 차단
증상
로봇 이동 중 흔들린 프레임에서 OBB 좌표가 퍼블리시되어 목표 위치가 틀어진 채 픽업 시도
원인
ROS2 토픽은 이동 중에도 계속 흐름. 검출 노드가 로봇 정지 여부를 인지하지 못한 채 좌표를 발행
해결
SetBool Service로 명시적 게이트 구현 :
이동 전 set_bool(False)로 퍼블리시 차단 → 정지 확인 후 set_bool(True)로 재개 → 첫 유효 좌표 수신 → 픽업 전 재차단
인사이트
"좌표는 로봇이 멈췄을 때만 유효" — 게이팅 패턴으로 이동/검출 간 타이밍 경쟁 조건 완전 제거

회고

배운 점

  • 제약이 곧 설계다. Depth 센서 없이 3D 좌표를 복원해야 한다는 제약이 있었고, "상자는 항상 테이블 위에 있다"는 물리적 사실 하나로 Ray-Plane Intersection을 풀 수 있었습니다. 주어진 조건 안에서 문제를 정확히 정의하면 복잡해 보이는 문제도 단순해진다는 걸 이번 프로젝트에서 직접 체감했습니다.
  • 독립성 있는 코드가 디버깅 시간을 줄인다. ROS2 노드로 작성하면 수정할 때마다 빌드·재시작이 필요하지만, 핵심 로직을 core/로 분리해두면 Python 스크립트로 바로 실행·검증이 가능합니다. 덕분에 캘리브레이션 수식 오류나 좌표 변환 버그를 로봇 없이 빠르게 찾아낼 수 있었습니다.
  • 캘리브레이션은 시스템의 기반이다. Hand-Eye 캘리브레이션 오차가 커지면 아무리 OBB 검출이 정확해도 파지 좌표가 틀립니다. 시스템 전체의 오차 예산을 먼저 설정하고, 각 단계의 허용 오차를 역산하는 방식으로 접근한 것이 유효했습니다.

아쉬운 점

  • 폐루프 제어를 구현하지 못했습니다. 현재는 촬영→계산→실행의 개루프(Open-loop) 구조라 파지 직전 로봇의 미세 떨림을 보정할 수 없습니다. Visual Servoing으로 전환했다면 성공률을 더 높일 수 있었을 텐데, 부트캠프 일정 안에서 구현까지는 시간이 부족했습니다.
  • 다양한 물체로 일반화하지 못했습니다. HSV 기반 OBB 검출은 신발 상자처럼 단색·직육면체 물체에 최적화되어 있습니다. 불규칙한 형태나 반사 표면에서는 검출 성능이 떨어질 수 있어, 실제 매장 환경 일반화는 추가 작업이 필요합니다.
  • 단독 통합 테스트 환경이 없었습니다. AMR·FMS·UI 팀과 협업하면서 통합 테스트를 위해 항상 전체 시스템이 켜져 있어야 했습니다. Mock 인터페이스를 만들어 두었다면 독립적으로 더 많은 케이스를 검증할 수 있었을 것입니다.

프로젝트를 마치며

이번 프로젝트는 "로봇에게 눈을 달아준다"는 것이 단순히 카메라를 연결하는 문제가 아님을 알게 해 준 경험이었습니다. 좌표계 변환 하나하나, 캘리브레이션 포즈 수집 방식, 이미지 처리 파이프라인의 각 단계가 서로 맞물려 있어서 한 곳의 오차가 최종 파지 위치에까지 영향을 줬습니다.

그 과정에서 가장 크게 느낀 것은, 좋은 엔지니어링은 문제가 생겼을 때 어디서 틀렸는지 빠르게 찾을 수 있는 구조를 미리 만들어 두는 것이라는 점입니다. 다음 프로젝트에서는 설계 초기부터 각 모듈의 검증 방법을 함께 정의하는 습관을 이어가려 합니다.
