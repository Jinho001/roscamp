프로젝트 배경

신발은 브랜드마다 사이즈 체계가 달라 실제로 신어보지 않으면 맞는지 알기 어렵습니다.
온라인 구매의 반품률이 높은 근본적인 이유입니다.
그렇다고 매장을 방문하면 직원의 응대가 부담스러워 자유롭게 신어보기 어렵다는 불편함도 있습니다.

이 두 문제를 동시에 해결하기 위해 "직원 눈치 없이 마음껏 신어볼 수 있는 반무인 신발 매장"을 목표로 삼았습니다.
AMR과 로봇팔을 연동해 고객이 선택한 신발을 자동으로 가져다주는 자동화 매장 시스템 Moosinsa를 구현했습니다.

프로젝트 목표

Depth 카메라 없이 2D 단안 RGB 카메라만으로 임의 위치·각도로 놓인 신발 박스를 인식하고 파지 좌표를 계산해 자율적으로 Pick & Place를 수행하는 비전 파이프라인 구축.

① Depth 센서 없이 3D 좌표 복원

Ray-Plane Intersection — "상자는 항상 Z_surface 위에 있다"는 물리적 제약 하나가 광선과 평면의 교점을 유일하게 결정합니다.

# core/coord_transform.py
ray_c = K_inv @ [cx, cy, 1.0]
ray_b = R @ ray_c
t = (z_surface - origin[2]) / ray_b[2]
P = origin + t * ray_b   # mm

오차 허용 기준 ≤5 mm — 그리퍼 파지 폭(약 40 mm)의 1/8 이내면 파지에 영향 없다는 오차 예산으로 설정. 트레이드오프: 물체가 평면 위에 있다는 도메인 가정 필요.

② Hand-Eye 캘리브레이션

AX = XB (Tsai-Lenz), 25포즈, Hand-Eye RMS 오차 1.245 mm.

# 각 자세마다
A_i = T_base2flange   # 관절각 → FK
B_i = T_cam2board     # solvePnP
# 25쌍 → Tsai-Lenz
X = cv2.calibrateHandEye(TSAI)

왜 Flange 기준인가: TCP는 그리퍼에 따라 달라지는 가변값. Flange는 공구 교체와 무관한 고정점이므로 그리퍼 교체 후에도 재캘리브레이션 불필요.

③ 이동 중 프레임 배제

로봇 이동 중 캡처된 OBB 결과를 사용하면 오파지 발생. move_to()가 완전히 반환된 이후에만 검출을 폴링하도록 순차 실행으로 보장.

# nodes/vision_pick_place_node.py
self._motion.move_to(observe_pose)         # blocking
flange = self._motion.get_flange_coords() # Flange 좌표
self._transformer.update_pose(flange)     # T_base2cam 재계산
obb = self._detector.wait_for_detection(timeout=10.0)  # 정지 후 첫 프레임

④ Clean Architecture (v1 → v2)

v1에서는 좌표 변환 코드가 ROS2 노드에 묶여 수정할 때마다 로봇 연결 + ROS2 부팅이 필요했습니다. v2에서 core/Node를 분리했습니다.

Detection Pipeline

OBB 검출 파이프라인

흰색 단색 상자 환경에서 딥러닝보다 빠르고 파라미터 조정이 직관적인 OpenCV 파이프라인.

단계 내용
① LAB CLAHE L채널(밝기)에만 CLAHE 적용. 색 정보(A, B) 유지한 채 조명 정규화 → HSV 범위 안정화
② HSV 마스킹 흰색 상자 HSV 범위 inRange. Morphology(CLOSE+OPEN)로 노이즈 제거 및 구멍 메움
③ minAreaRect 최대 면적 윤곽선에서 최소 면적 회전 직사각형 추출 → cx, cy, w, h, θ

Raw → HSV Binary → Morphology → 최종 OBB 검출 결과 비교

HIL Troubleshooting

체계적 오차 해결 2건

격리 스크립트로 추측 없이 원인을 확정했습니다.

Z축 +110 mm → 0 mm
증상
로봇이 상자보다 정확히 110 mm 높은 공중을 파지 시도
원인
z_surface 측정 시 그리퍼 tip이 상자에 닿은 상태에서 Flange 좌표를 읽음. Flange는 tip보다 그리퍼 길이(110 mm) 위 → z_surface 과대 측정 → Ray-Plane 결과 전체 +110 mm
보정
1차: 측정값에서 그리퍼 길이 수동 차감 / 개선: set_end_type(1) TCP 모드로 전환 후 측정
Y축 +16.3 mm → 허용 기준 내
증상
X축은 정확한데 Y 방향으로만 일정하게 16.3 mm 편향
원인
verify.py Step B로 알려진 위치에서 16.3 mm 재현 확인. Tsai-Lenz local minima 수렴 + 카메라 브래킷 조립 공차 누적 추정
보정
반복 측정에서 편향이 안정적으로 재현 → pick_offset_mm: [0, -16.3, 0] 정적 보정
